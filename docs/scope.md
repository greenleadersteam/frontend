# Назначение и границы

## Назначение

Веб-клиент — оболочка над сервером расчёта озеленения. Пользователь загружает архив с подосновой и инженерными сетями, сервер строит план посадок с нормативными отступами и возвращает результат. Клиент показывает этот результат так, чтобы специалист мог проверить каждое решение: где посадка, от чего она отступает, на каком расстоянии и по какому пункту какого акта. Кроме того, клиент позволяет поправить расстановку, выгрузить результат и совместить контур участка с картой города в модуле геопривязки.

Пользователи — проектировщики озеленения, специалисты Департамента природопользования и охраны окружающей среды Москвы, участники согласования.

## Что входит в эту версию

- **Проекты.** Список с состоянием обработки, создание, удаление.
- **Загрузка подосновы.** Один ZIP или несколько DXF, которые браузер упаковывает в ZIP сам. Архив проверяется до отправки: сигнатура, наличие DXF, размер до 100 МиБ, имена в кириллице. Загрузка идёт с прогрессом.
- **Состояние обработки.** Этапы сервера, прогресс, ошибки с объяснением и действием. Опрос сервера идёт, пока обработка не закончена, и не дольше 30 минут.
- **План посадок на карте.** Деревья, кустарники, газон, «можно сажать», зоны запрета, граница участка, исходные объекты подосновы, отклонённые места.
- **Объяснение каждой посадки.** Проверки с размерными линиями, нормой, актом и пунктом; отдельно — что не проверялось. Подробно — в [interpretability.md](interpretability.md).
- **Правка расстановки.** Перемещение, добавление, удаление, смена породы, отмена и повтор; статус правленой посадки пересчитывается сразу. См. [editing-and-export.md](editing-and-export.md).
- **Выгрузки.**
  - DXF сервиса, он же с правками на слое результата и отдельный слой посадок с правками — в координатах чертежа;
  - ведомость посадок и ведомость озеленения по породам, в Excel (.xlsx) и CSV;
  - отчёт для согласования, печатается браузером в PDF.
- **Модуль геопривязки.**
  - ручное совмещение контура с картой и привязка по опорным точкам с оценкой точности;
  - эталоны и выгрузка;
  - привязка проекта без геопривязки сервера, в том числе проекта, упавшего на геопривязке, — только в «Демо», как цель следующей версии (см. ниже).

  См. [georeference.md](georeference.md).

- **Работа без интернета.** Своя подложка карты (файл PMTiles на своём сервере), локальные шрифты и иконки, ни одного обращения к внешним сервисам, если в конфиге не включён космоснимок.
- **Режим «Демо»** — показ всех функций на демонстрационных данных в браузере.

## Что на развитие

- **Функции, которых ждёт сервер.** Клиент уже умеет с ними работать и включает их по списку возможностей сервера (см. ниже). Контракт этих запросов — в `contracts/openapi.proposed.yaml`, он передан разработчику сервера.
- **Привязка проекта к карте.** Применить привязку из модуля может только сервер (`PUT /georeference`), и это следующая версия бэкенда. До неё кнопок привязки на экране проекта нет; в «Демо» функция показана как цель.
- **Версии плана посадок на сервере.** Модель бэкенд-разработчика, контракт с дополнениями фронтенда — в `contracts/openapi.proposed.yaml`. Клиент работает с ней в «Демо»; на стенде правки — черновик в браузере.
- **Работа без сети на сервере** — следующая версия бэкенда.
- **Вход пользователей и права.** Схема аутентификации не выбрана. Требования к ней уже заданы:
  - токены не хранятся в `localStorage`, `sessionStorage` и IndexedDB, предпочтительна сессионная cookie с `HttpOnly`, `Secure`, `SameSite`;
  - запросы, меняющие данные, несут CSRF-токен;
  - на ответ 401 — один общий сценарий повторного входа.
- **Сквозные тесты в браузере.** Сейчас есть модульные тесты и тесты экранов в jsdom.
- **Космоснимок в закрытом контуре.** Сейчас снимок — внешний сервис Esri, и в контуре заказчика он выключен. Для контура нужен свой источник снимков.
- **Размер кроны по породе.** Сейчас радиус кроны на плане и в слое DXF задаётся по типу посадки: 1,5 м у дерева, 0,35 м у кустарника (`entities/project/lib/plan-projection.ts`, как у сервера).

## Режимы «Сервер» и «Демо»

|              | «Сервер»                                          | «Демо»                                                                                                                                                  |
| ------------ | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Данные       | Настоящий сервер через `/api`                     | Демонстрационные данные в браузере (MSW)                                                                                                                |
| Что доступно | Базовый API и возможности из `serverCapabilities` | Все возможности контракта-предложения                                                                                                                   |
| Зачем        | Работа с реальными проектами                      | Показ функций, которые сервер ещё не реализовал; проверка интерфейса без сервера                                                                        |
| Как отличить | Переключатель в шапке на «Сервер»                 | Переключатель на «Демо», под шапкой постоянная метка «Демонстрационные данные», у проектов подпись «Демонстрационный проект», в отчёте — крупная плашка |

Переключатель есть, только если в `config.json` задано `"demoMode": "available"`. При `"off"` клиент работает только с сервером, код демо не загружается, а оставшийся от прошлого показа служебный обработчик браузера снимается при старте (`src/shared/config/data-source.ts`).

Демо не выдумывает право: нормы и породы в демонстрационных данных взяты только из сверенных таблиц `contracts/norms-verified.md` и `contracts/species-verified.md`.

В режиме «Сервер» код демо не скачивается: демо — отдельный ленивый чанк сборки, его загружает только выбор «Демо».

## Возможности сервера

Что сервер умеет сверх задеплоенного API, клиент не угадывает по ошибкам 404: администратор перечисляет это в поле `serverCapabilities` файла `config.json`. Без возможности запрос не уходит, а интерфейс работает на базовом API. В «Демо» включены все возможности.

Колонка «Сейчас на сервере» — по проверке стенда `app.greenleaders.online` 28.09.2026: его `config.json` объявляет пустой список `serverCapabilities`.

| Функция                                                                 | Возможность          | Без неё                                                      | Сейчас на сервере |
| ----------------------------------------------------------------------- | -------------------- | ------------------------------------------------------------ | ----------------- |
| Исходные объекты на плане, панель «Объект», расстояние прямо до объекта | `obstacles`          | Проверки по зонам запрета                                    | нет               |
| Отклонённые места на плане и в ведомости                                | `rejected`           | Слоя и списка нет                                            | нет               |
| Акт, пункт, текст и источник нормы                                      | `norms`              | Норма и цитата из `/zones`, основание — по сверенной таблице | нет               |
| Расстояния и нормы сервера в карточке посадки                           | `explanationChecks`  | Расстояния считает клиент                                    | нет               |
| Порода посадки, «Почему эта порода»                                     | `species`            | «Дерево» или «Кустарник»                                     | нет               |
| Версии плана посадок на сервере                                         | `plantingEdits`      | Черновик в браузере                                          | нет               |
| DXF версии плана посадок от сервера                                     | `editedDxf`          | Слой посадок с правками собирает браузер                     | нет               |
| Выбор главного чертежа, повторная обработка                             | `runs`               | Объяснение и «Загрузить другой архив»                        | нет               |
| Привязка проекта на сервере                                             | `manualGeoreference` | Кнопок привязки на экране проекта нет                        | нет               |
| Проект без области участка (бэкенд решил не делать)                     | `optionalBbox`       | Область участка задаётся в мастере                           | нет               |

Список возможностей и что за каждой стоит — `src/shared/config/runtime-config.ts` (`CAPABILITIES`) и описание контракта-предложения.
